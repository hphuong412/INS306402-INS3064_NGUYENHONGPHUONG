3) Short Explanation
The minimal code follows the MVC structure. Request.php is the Model, RequestController.php is the Controller, and index.php and show.php are the Views. The file public/index.php is the entry point of the application.

D) REFLECTION
1) Which parts of your design are Model, View, and Controller?
In my design, the Model includes Request, RequestRepository, RequestService, and RequestValidator because they handle data and business logic. The View includes requests/index.php and requests/show.php because they display information to the user. The Controller is RequestController, which receives requests, calls the model layer, and selects the correct view.
2) Where should validation happen, and why?
Validation should happen in RequestValidator or inside the service layer before data is saved. This is better because validation has its own responsibility. It should not be placed inside the view. This design follows the Single Responsibility Principle and makes the code easier to maintain.
3) What would break if you put SQL inside a View file?
If SQL is placed inside a View file, the view will mix presentation with data logic. This makes the code harder to read, test, and maintain. It also breaks the MVC structure and the Single Responsibility Principle. If the database changes, the View file would also need to change.
